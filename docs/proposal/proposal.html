1Executive summary

The company's historical research holds a lot of value, but it is locked inside individual PDF reports. Customers have to open reports one by one to find information and connect it across years. This proposal puts forward an AI research assistant. An authorised user picks the research libraries they want, asks a question in plain language, and gets an answer built only from those reports. Every statement cites the report and page it came from.

The concept is already built as a working prototype, not just a design. Today it:

  • ingests real PDF reports page by page, with an exact page index for every page
  • finds relevant pages with hybrid search, combining meaning-based and keyword search
  • writes answers with a three-agent pipeline: a Query Agent plans the search, an Answer Agent writes the cited answer, and an Evaluator Agent checks every claim against its source
  • opens any citation in a built-in PDF viewer, at the cited page with the evidence highlighted
  • restricts each user to the libraries they're authorised for, enforced in the database itself
  • gives administrators control over documents, libraries and users, plus a quality dashboard

2The problem

The company has a substantial body of historical research, but it is published as PDF reports. That causes three problems:

  • Finding information is slow. A user has to know which report to open, then search inside it. Questions that span several reports or years, such as "how has the view on X changed since 2022?", mean reading many documents.
  • Value goes unused. The insight is there, but the format limits how easily customers can interrogate it. Older reports are rarely revisited.
  • An enterprise build is a big bet. Committing to a full enterprise knowledge platform before the concept and its customer value are proven would need a much larger investment.

Desired outcome

A working prototype where an authorised user can ask questions across a selected company's research library and get useful, source-grounded answers they can verify. That lets the business demonstrate and assess the concept before deciding on a production build.

Design principles

PrincipleWhat it means in the design
Grounded, not generativeThe model may only use text retrieved from the selected reports. If the reports don't cover a question, the assistant says so rather than guessing.
Verifiable in one clickEvery factual sentence carries a citation. Clicking it opens the PDF at the exact physical page, with the supporting sentence highlighted.
Secure by defaultAccess is checked in the database (row-level security), not only in the user interface. A user cannot retrieve text from a library they haven't been granted.
Small to start, easy to growManaged services (Supabase, Vercel, DeepSeek) mean no servers to run. Each component can later be swapped for an enterprise equivalent.

3The solution: what users do

There are two roles. Administrators build the libraries; users ask questions and verify answers.

Administrator workflow

  1. Create a library per company or research collection.
  2. Upload PDF reports and tag them with one or more libraries. Indexing runs automatically and shows progress page by page.
  3. Invite users and choose which libraries each one can search.
  4. Monitor answer quality, feedback and usage on the Insights dashboard.

User workflow

  1. Sign in, by invitation only.
  2. Select the libraries to search: one company or several.
  3. Ask a question in plain language. The answer streams in with citation chips such as S1.
  4. Click any citation to open the source page, and rate the answer.

6Ingestion, indexing and retrieval

Reliable page references

Published reports often number pages with roman numerals in the front matter, or restart numbering in each section. The prototype therefore does not rely on the printed page number. It records every page by its physical position in the file (page_index), and every citation uses that number. The printed label is kept only for display. Of the 10 test reports collected (5 Federal Reserve, 5 BIS), 6 have printed page numbers that differ from their physical positions; the viewer shows both, e.g. "page 51 (printed 31)".

Efficient, resumable ingestion

  • Direct upload. The browser uploads each PDF straight to Supabase Storage with a signed URL, which avoids API request-size limits.
  • Batched processing. The API processes 25 pages per request and reports progress. A failed document can resume where it stopped, and re-running a batch is safe.
  • Text cleanup. Headers and footers repeated on more than half the pages are removed, and words hyphenated across line breaks are rejoined.
  • Quality flags. Pages with no extractable text, such as scanned images or blank dividers, are flagged in the admin panel.

Hybrid retrieval

  • Each page is split into overlapping ~1,800-character chunks, the size the embedding model reads well. Every chunk keeps its page number.
  • A single SQL function, match_chunks, runs two searches inside the database: semantic similarity (pgvector, HNSW index) and keyword search (Postgres full-text). It merges their rankings with Reciprocal Rank Fusion. Semantic search finds paraphrases; keyword search catches names, tickers and exact phrases.
  • Hits are rolled up to pages. A page scores its best chunk for each sub-query, so evidence found by several sub-queries ranks higher. The top 8 pages go to the Answer Agent, with at most 4 per report so several reports can contribute.
  • The Answer Agent gets the whole page, not a fragment, so it has full context.

7Grounded answers: the multi-agent pipeline

Three specialised agents handle each question. Splitting the work keeps each prompt simple and makes the answer checkable.

AgentModelResponsibility
Query Agentdeepseek-flash (no reasoning, for speed)Turns the question and chat history into a standalone question, 1–3 focused sub-queries for comparative or multi-period questions, and keywords for the keyword search.
Answer Agentdeepseek-v4-pro (low reasoning effort)Answers only from the retrieved pages and cites every factual sentence. Points out changes between reports and periods. If the sources don't cover the question, it says so instead of guessing.
Evaluator Agentdeepseek-flash (low reasoning effort)For every claim, records supported, partial or unsupported, whether the citation is correct, and a verbatim evidence quote. Produces a grounded score from 0 to 1. Citations to sources that don't exist are always marked wrong.

Quality gate. If any claim is unsupported, or the grounded score is below 0.75, the answer is rewritten once using the evaluator's findings and checked again. If it still fails, it is shown with a "Low confidence: verify before use" badge rather than hidden.

8Citations and verification

Trust depends on users being able to check an answer quickly. The prototype makes verification a single click.

  • Each [S#] marker in an answer is a clickable chip. Hovering shows the report title and page.
  • A Sources list under every answer gives the report name and physical page for each citation, plus the printed page number when it differs.
  • Clicking a citation opens the PDF in a side panel at the cited page. The evaluator's evidence quote is highlighted on the page and scrolled into view.
  • Users can page through the document, zoom, return to the cited page, or open the original PDF in a new tab.

9Access control

Restricting each user to the research libraries they are entitled to is enforced at several layers, so a bug in one layer doesn't expose data.

LayerControl
IdentitySupabase Auth with email and password or a one-time link. Accounts are invitation-only; there is no public sign-up.
Roles and grantsUsers are admin or user. Admins grant each user specific libraries, and the label on a report decides which libraries it belongs to.
Database (main control)Postgres row-level security on documents, pages, chunks, libraries, conversations and messages. A user sees a document only if it carries a library they hold. The search function runs with the caller's permissions, so naming another library's id still returns nothing.
APIVerifies the user's token, intersects the requested libraries with the user's grants before any search, and queries the database with the user's own token.
FilesPDFs sit in a private bucket. A short-lived signed URL is issued only after the database confirms the user can see the document.
PrivacyConversations are private to their owner. Administrators can read answers in Insights, so they can review quality.
Tested. 24 automated database checks run the migrations against a real Postgres with pgvector. They confirm that users cannot see other libraries' documents, chunks or search results, cannot promote themselves or grant themselves access, and cannot read other users' conversations.

10Administration

Administrators run the libraries without technical help.

  • Documents: drag-and-drop upload with per-file progress, library tagging, status (processing, ready or failed) with error details, resume, re-index and delete, and warnings for pages without text.
  • Libraries: create, rename and colour libraries; see document and user counts; bulk-assign reports.
  • Users: invite, set roles, and grant libraries, as shown in figure 7.
  • Insights: documents indexed, questions asked, average groundedness, answers revised by the evaluator, the helpful rate, and a filterable question log with latency and token usage.

11Evaluating answer quality

Quality is measured in two complementary ways: continuously on every live answer, and offline against an expert-written test set before any change ships.

Live, on every answer

  • The Evaluator Agent's verdict, grounded score and claim checks are stored with the answer.
  • Users rate answers with thumbs up or down and an optional note.
  • Insights tracks the trends and lists low-confidence and no-source questions. These show gaps in the library or in retrieval.

Offline, against a golden set

A domain expert writes 30–50 questions across four types: single fact, cross-report synthesis, comparison over time, and unanswerable (the assistant must decline). Each question records the expected report pages and a reference answer. The included runner (evals/run_eval.py) sends them through the same pipeline the app uses and reports:

MetricWhat it measuresTarget
Recall@10, MRRRelevance of retrieval: were the expected pages found, and how high did the first one rank?≥ 0.85
Citation accuracySource accuracy: does each cited page actually contain the claim? Scored by an LLM judge, with about 20 verdicts checked by hand.≥ 0.90
FaithfulnessShare of claims supported by the cited sources.track
Correctness, relevanceAnswer quality against the expert's reference answer, on a 1–5 scale.track
Refusal accuracyUnanswerable questions are declined, not answered.≥ 0.90
Latency, tokensTime to answer (p50/p95) and cost per question.track

Reports are saved as CSV and markdown, so runs before and after a change to prompts, chunking or retrieval can be compared side by side.

Findings from early testing

Strong single-report answer. "What does the BIS 2024 report say about how central banks can use artificial intelligence?" produced a structured answer citing four pages (pages 18, 111, 112 and 113). The evaluator rated it 100% grounded, and the evidence was highlighted correctly in the viewer (figures 1, 5 and 6). Time: 18.8 s.
Retrieval weakness found. For a broad comparative question about inflation across the 2022 and 2024 reports, search returned mainly reference lists and endnotes. Those pages are dense with titles containing the search terms. The assistant correctly said the sources didn't contain the assessment instead of inventing one, but the right pages were missed. Fix planned: detect bibliography and endnote pages at ingestion and exclude or down-weight them in search, then confirm with the golden set.

These are early, qualitative observations from a small number of questions. They are not yet a measured benchmark; the golden-set runs during the client engagement will provide one.

13Proving customer value: 10-week client engagement

The prototype is ready to put in front of the client. Over 10 weeks we hold a weekly meeting with the client: we show progress in the live prototype, review results together, and agree the priorities for the next week. Every week is shaped by the client's feedback, and the engagement answers the question that matters before a larger investment: do customers get faster, trustworthy answers from the research they already pay for?

14Risks, limits and the path to production

Known limits of the prototype

LimitImpact and mitigation
Reference and endnote pages can crowd out body textSeen in testing. Exclude or down-weight them at ingestion (engagement week 2).
Embedding model is small and English-only (gte-small)Hybrid keyword search compensates. Swapping to a larger or multilingual model changes one file.
Scanned PDFs, tables and chartsPages without a text layer are flagged but not indexed. Tables are read as plain text. Add OCR and layout-aware extraction in production.
Response time of 19–28 sThe answer streams as it is written, so text appears sooner. The evaluator check and model reasoning add time; reasoning effort is configurable per agent.
Evaluator judges itself generously at timesAn honest "not covered" reply was rated 100% grounded. Spot-check judge verdicts by hand and consider a judge from a different model family for offline evaluation.
Data sent to a third-party model APIOnly retrieved excerpts are sent, never whole libraries. Confirm the provider's data terms, or use an approved provider or region, before using sensitive research.

What a production build would add

  • OCR and layout-aware extraction for tables and figures
  • A background ingestion queue for large volumes
  • A re-ranking step after hybrid search
  • SSO/SAML and automated user provisioning (SCIM)
  • Audit logging of document access and answers
  • Per-tenant isolation for each customer
  • Usage metering, quotas and rate limits
  • Data-retention and deletion controls
Conclusion. The concept is no longer theoretical. A working prototype already answers questions across real research reports with verifiable, page-level citations and database-enforced access control. A 10-week engagement with weekly client meetings is a low-cost way to measure its value before committing to a full enterprise implementation.
